# MVP Design Worksheet (expanded)

**Source:** The Founder's Field Manual, Chapter 6 — The MVP: Build to Learn, Not to Launch
**Agent use:** When a subscriber is about to build, has been building too long, or asks "what features should my MVP have?" The reframe: an MVP is an experiment that answers a question, not a small product.

## Step 1 — Name the dangerous question
What single question do the next twelve months depend on? Write it as a yes/no question. If you cannot, you have a project, not a question.

*Agent check:* good questions are about customer behavior ("Will operations managers upload their real data in week one?"), not about the product ("Can we build it?"). Engineering feasibility is rarely the dangerous question.

## Step 2 — Design the experiment
The cheapest version that produces a *believable* answer. Ladder of shapes, cheapest first: explainer video → landing page with a price and a buy button → concierge service (do it manually) → Wizard-of-Oz (fake the backend) → clickable prototype → single-workflow product. Pick the cheapest shape you would still trust the answer from.

## Step 3 — Run the MoSCoW
- **Must-Haves:** the experiment fails without them
- **Should-Haves:** valuable, not decisive
- **Could-Haves:** nice, later
- **Won't-Haves (yet):** named explicitly so the team stops relitigating them

**Survival test:** would each Must-Have still be in if you had to ship next week? If not, demote it.

## Step 4 — Pick testers and define success
Name 5–20 specific people or accounts who will use it. Decide the feedback channels (interviews, usage telemetry, paid pilots). Define the success threshold *before* launch — what number means yes, what number means no.

## Common failure patterns
1. **The stealth full product** — "MVP" with a 6-month roadmap. If the build exceeds 6 weeks, the agent should challenge the experiment design.
2. **Unfalsifiable success** — "we'll see how people respond." No pre-committed threshold means every result gets rationalized as encouraging.
3. **Testing on the wrong people** — friendly design partners who don't match the actual buyer. Testers must look like the paying customer.
4. **Polish as procrastination** — founders (especially technical ones) refining UI instead of shipping the answer. The MVP's job is information, not admiration.

## Output the agent should produce
A one-page experiment brief: the yes/no question, the experiment shape and why it's believable, the MoSCoW table, the named testers, the success/failure thresholds, and a ship date no more than six weeks out.
